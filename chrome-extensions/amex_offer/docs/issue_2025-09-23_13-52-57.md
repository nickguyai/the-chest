### analysis

Goal: Automate clicking each Amex offer’s “Add to list” button (`data-testid="merchantOfferListAddButton"`) and capture key details from each offer into a structured dataset that can be exported (JSON/CSV).

Observations:
- The sample page (`sample.html`) contains repeating offer rows. Each row includes:
  - Title in `h3 > span` inside a `div[data-testid="overflowTextContainer"]`.
  - Description in a sibling `div[data-testid="overflowTextContainer"] > span` (not inside `h3`).
  - Expiry in a `p` element containing text like “Expires …”.
  - Merchant logo `img` near the left within the same row container.
  - The actionable button with `data-testid="merchantOfferListAddButton"`.
- On the real site, buttons perform networked actions; on the static sample page, clicks won’t change the DOM but should still be fired sequentially.
- Running against local `file://` URLs requires enabling “Allow access to file URLs” for the extension in Chrome.

What to capture per offer:
- `title`, `description`, `expires`, `imageSrc`, `clickedAt` (ISO timestamp), and a simple `id` (hash of title+description) for deduplication.

Interaction model:
- A Chrome extension with a popup that:
  - Finds all `merchantOfferListAddButton` buttons on the page.
  - Sequentially scrolls to and clicks each (with a small delay between).
  - Extracts and saves offer details to `chrome.storage.local`.
  - Lets the user export saved data as JSON or CSV.

Key considerations:
- Selector robustness: Locate the nearest ancestor container around each button and query for title/description/expiry within that scope so minor class name changes don’t break extraction.
- Rate limiting: Use a small delay (e.g., 250–500ms) between clicks to reduce risk of throttling or UI hiccups.
- Idempotency: Mark processed buttons and deduplicate offers in storage by a stable `id`.
- Permissions: `storage`, `activeTab`, `downloads`; host permissions for `americanexpress.com` and (optionally) `file://*/*`.

### fix_plan

1) Scaffold MV3 extension
2) Implement content script: scan, extract, click, save
3) Build popup UI: Start, Export JSON/CSV, Clear
4) Add background service worker for file downloads
5) Wire messaging between popup ⇄ content ⇄ background
6) Document usage (load unpacked, enable file URLs, run on sample)

Implementation outline:
- Manifest v3 with `action.default_popup`, `background.service_worker`, `content_scripts` on `<all_urls>` (script early-returns unless target buttons exist), and needed permissions.
- Content script functions:
  - `findOfferButtons()` → visible `button[data-testid="merchantOfferListAddButton"]` list.
  - `extractOffer(container)` → title/description/expiry/image.
  - `clickAllSequentially(delayMs)` → scroll, click, collect, save, dedupe.
  - Message handlers: `collect_offers`, `get_offers`, `clear_offers`, `get_counts`.
- Popup UI: buttons for actions + live counts, uses `tabs.sendMessage` to control the page and retrieve data.
- Background: handle `download` messages, create Blob URLs, invoke `chrome.downloads.download`.

Privacy note:
- The extension does not store or export `pageUrl` to avoid exposing account-identifying information.

Notes for sample.html:
- When testing locally, load the extension, allow file URL access in Chrome, open `sample.html` in a tab, then use the popup to “Scan + Click All” and export.
